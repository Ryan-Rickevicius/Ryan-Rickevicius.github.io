This is an authoring example, not a completed analysis. Keep **Draft** enabled while editing. It is excluded from the public website, although files saved to a public GitHub repository remain visible in the repository.

## The question

Explain what you wanted to investigate and the decision it could inform.

## Data and approach

Identify the source, period, sample, and preparation. Describe the analysis and your own contribution.


| Item | What to describe |
| ----------- | -------------------------------- |
| Data source | Where the observations came from |
| Sample | What was included or excluded |
| Method | How the question was examined |


## Findings

Add actual results and explain what they show. Upload a chart before including it in the article. A Markdown image reference looks like this:

```markdown
![A description of what the chart shows](your-chart.png)
```

Use the editor's image controls for normal posting. Give charts readable axis labels, units, and a useful caption.

## Code or supporting methods

Code blocks can explain a method when they help a reader. This small example is a formatting demonstration:

```r
# Load an analysis dataset.
analysis_data <- read.csv("your-data.csv")
```

## What this means

Explain how the findings inform the original question. Keep observed results separate from assumptions and recommendations.

## Limitations

Describe uncertainty, missing information, and the limits of the method.

## Sources and deliverables

Link the data, relevant research, or available code. Use the editor's Downloads fields to attach a report and its label. Use the interactive section fields for supported chart or dashboard URLs.
